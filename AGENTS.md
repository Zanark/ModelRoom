# Model Room contributor contract

## Product and authority

Model Room is a static, local-first inspection workspace for models authored
by the user's coding agent. Do not present preset switching or brief saving
as arbitrary AI generation. No API keys, remote inference, uploads, telemetry,
accounts, executable model uploads or runtime CDN dependencies.

The current request authorizes implementation, local hosting, documentation,
TODO/issue/Project tracking and an owned context refresh. On 2026-11-08 the user
explicitly requested committing and pushing the working foundation before
rigging changes. No public-site deployment was requested. Preserve unrelated work. Do not modify
BowserBoy or its private store; it is a read-only methodology reference.

## Stack and model contract

- Three.js **0.186.1**, browser Canvas 2D and JavaScript ES modules author models.
- Node/npm/Vite build and serve them; Playwright verifies actual browser outcomes.
- Blender is an interchange target, not a requirement for authoring.
- One unit = one meter, Y up. Name geometry and material roles.
- Export only the authored object root; never the viewer floor, lights, camera,
  environment or selection helpers.
- Prefer standard metallic/roughness PBR materials, embedded textures, positive
  scales and finite geometry. Bake procedural texture color into a canvas/image,
  not an unportable custom shader. Do not promise CAD, quads or modifier stacks.
- Record dimensions, origin, hierarchy, moving pivots, assembly, resource ownership
  and relevant visual/interaction invariants. Validate inputs before allocation.
- Reuse the contract in docs/AGENT-WORKFLOW.md when adding another subject.

## Workflow

Read README, TODO/00_INDEX.todo, the affected workstream and the relevant
architecture/model/research documentation. Work in a bounded change, run the
smallest applicable checks, inspect real output, then update the ledger and guides.
Keep numbered workstreams with all eight required fields. Index 00 and ledger 02
are excluded from finite issue tracking. Keep technical evidence distinct from
user aesthetic approval, public publication and actual Blender validation.

Follow docs/GITHUB-TRACKING.md for existing issue/Project identities. Never
overwrite managed remote changes or mint duplicate cards on uncertain writes.
Do not include local context, prompts, reference images or secrets in issues.

## Commands and boundaries

`npm run dev`: loopback 4173, strict port; do not kill someone else's listener.
`npm run check`: source syntax and repository document links.
`npm test`: deterministic model/format contracts.
`npm run build`: Vite production artifact.
`npm run test:browser`: actual browser interactions and exports; starts its own
isolated loopback server on 4174. Use the existing supported Edge installation.
Dependency installs follow manifest changes or actual missing-dependency failures.

Private local evidence goes in ignored `.local`. `.agent-context` is private,
owned by this base. Resolve it through Context Mesh, preserve session-specific
personas, and never write sibling stores. Never export private history as docs.
